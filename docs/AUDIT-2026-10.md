# Vectis audit — 3 Oct 2026

A read-through of the whole app (~10,700 lines), looking for bugs, risks
to saved data, conflicts with the suite's product values, and polish.
Nothing here is fixed yet unless marked. Ordered by how much it matters.

## Fixed in the same session

- **Tray swipe flipped the day.** The day-change swipe was on the whole
  screen, so reaching the end of the tray (or the goals strip) changed day.
  Now attached to the grid only.
- **Tray items couldn't be dropped.** The drop target sat on the events
  layer, whose real size is one block at the top (blocks are positioned
  with `.offset`, which doesn't change layout size). Now the whole grid.

## High — risk to saved data or trust

> Items 1 and 2 fixed 3 Oct 2026 (Batch A). Unreadable files are renamed to
> `<name>.unreadable-<timestamp>.json` in Documents; all 15 types now have
> hand-written Codable in extensions (memberwise inits kept). Verified with a
> standalone test: old-format JSON loads, missing fields default, round trip
> matches, corrupt file is set aside. Note: set-aside files are only
> reachable via Xcode (Devices → download container) unless file sharing is
> turned on in Info.plist.

1. **An unreadable save file gets overwritten.** `PersistenceManager.load`
   returns `nil` both for "no file yet" and "file exists but won't decode".
   Stores treat both as first launch: Goals and Notes load sample data,
   the rest start empty — and the next edit saves over the real file.
   Fix: if the file exists but fails to decode, move it aside
   (e.g. `goals.unreadable-2026-10-03.json`) before carrying on, so
   nothing is ever lost silently.

2. **Automatic `Codable` on persisted models** (breaks the suite's first
   engineering rule). Adding any field to these would fail decoding, which
   combined with (1) wipes the data:
   `CalendarCategory`, `EventPart`, `Milestone`, `GoalNote`,
   `ScheduleVersion`, `Notebook`, `Note`, `ChecklistItem`, `Person`,
   `CustomApp`, `PendingLaunch`, `CalendarHours`, `AppearanceSettings`,
   `PlanReviewStore.SavedSettings`, `PeopleStore.BirthdayPrefs`.
   `Milestone`, `GoalNote` and `ScheduleVersion` live inside `Goal`, so one
   of them failing loses every goal. Fix: hand-write all of them.

> Items 3, 6 and 11 fixed 3 Oct 2026 (Batch B). `Goal.firstDayKey` = earlier
> of `createdDate` and the oldest logged day; `isScheduled(on:)` is false
> before it. Challenge habits now get `createdDate` = challenge start.
> `missNudge` is nil once done today. `dayKey` built from date components
> (verified identical to the old formatter on 62,595 dates / 5 time zones).
> Trade-off: days before a goal began can't be retro-logged from its dots.

3. **New goals are counted as missed before they existed.**
   `isScheduled(on:)` ignores `createdDate`. A daily goal created today
   immediately shows "Missed 60 in a row — worth picking back up today",
   13 grey dots in its history, and gets flagged in the evening review.
   Same for challenge habits before the challenge's start date.
   Fix: treat days before the goal began as not scheduled. Use the earlier
   of `createdDate` and the oldest completion, because goals saved before
   `createdDate` existed got "now" as their default.

## Medium — visible bugs

> Items 4, 7 and 9 fixed 3 Oct 2026 (Batch C), built but not yet checked on
> screen. `DayBlocks.blocks(on:)` in CalendarHelpers.swift is now the single
> source for the Daily grid, Home "Right now" and the commitment bar. The grid
> positions blocks by minutes into the shown day (clock-based, DST-safe),
> clipped to the visible hours; blocks with nothing visible are skipped.
> Grid hour labels, block times and `Goal.scheduledTimeText` follow the
> phone's 12/24-hour setting.

4. **Blocks that cross midnight draw wrong on the Daily grid.** Position
   uses clock time only, so 11 PM–12 AM becomes a 16pt sliver, and a
   Fri 10 PM–Sat 1 AM event shows at 10 PM on both days. Fix: measure
   minutes from the start of the day being shown, clamped to the grid.

> Items 5 and 8 fixed 3 Oct 2026 per Riley's decisions. 5: changing the time
> of one occurrence asks "This day only" / "This and all future days".
> This day: per-day overrides (`timeOverrides`, new `durationOverrides`).
> Future: `CalendarStore.changeTimesFromOccurrence` ends the series the day
> before and starts a new one (overrides and skipped days split by date),
> so earlier days keep their real times. 8: restart keeps
> every tick; `Goal.statsStartDate` makes dots, "times done", rates and miss
> counts start from the restart day (`statsFirstDayKey`).

5. **Changing a repeating event's end time is silently ignored.** The
   editor saves start changes as a one-day override but drops any
   duration change entirely. Decide: should it change the series length
   (simplest), or need a per-day duration override?

6. **The miss nudge stays after you've picked it back up.**
   `consecutiveMisses` counts from yesterday, so ticking a goal today
   still shows "worth picking back up today". Hide it when done today.

7. **"What's on today" is built in three places that disagree.** The
   Daily grid includes placed tasks; Home's "Right now" doesn't (it says
   "Nothing scheduled" during a task you placed); buffer awareness has its
   own copy. Fix: one shared `DayBlocks.blocks(on:)` used by all three.

8. **Restarting a challenge erases habit history.** *Decided 6 Oct 2026:
   keep history. Done in the web app; the Swift app still wipes.* `restartChallenge`
   sets `completions = [:]` on every linked habit — conflicts with "the
   record is truthful". Challenge progress can count from
   `challengeStartDate` instead, keeping past attempts in the record.
   Riley's call, since it changes what a restart means.

## Low — polish

> Items 10, 12 and 13 fixed 3 Oct 2026; every audit item is now addressed.
> 10: VoiceOver labels on all icon-only buttons (menu, day/month arrows,
> counters, delete, add, unlink, heading, contact actions). 12: comment fixed.
> 13: `CalendarEvent.occurrenceActuals` / `occurrenceEstimates` (per day,
> estimate frozen on first log, block shows the actual for that day only,
> split with the series by date). Not done: parts don't get a share of an
> occurrence's actual the way a one-off's parts do.
>
> Found along the way and fixed: (a) Long-Term opened repeating events with
> their FIRST day's date, so one-day edits/deletes/logs hit the wrong day —
> it now passes that day's occurrence (`timedEvents(on:)`); (b) on a one-off
> event, tapping Save after "Log it" wiped the log (save wrote back the
> snapshot) — save now starts from the live event and Log it updates End.

9. **Times are hard-coded to 12-hour AM/PM** on the grid labels and in
   `Goal.scheduledTimeText`, ignoring a 24-hour phone setting. Use
   `Date.formatted(date: .omitted, time: .shortened)` like the rest of
   the app does.
10. **No accessibility labels anywhere.** VoiceOver reads icon-only
    buttons (menu, day arrows, etc.) by symbol name, e.g.
    "line.3.horizontal". Add `.accessibilityLabel` to each.
11. **`Goal.dayKey` builds a new `DateFormatter` on every call.** It's
    called hundreds of times per redraw (history dots, 60-day miss
    counts), including every frame while dragging. Build the string from
    date components instead — faster, same output.
12. **Stale comment:** `CalendarEvent.isFlexible` says "Nothing reads this
    yet"; the planning popup does.
13. **No actual-time logging for repeating events** (the button is hidden
    for them). Weekly classes are prime calibration data, so estimate
    calibration (2.5) will need a per-occurrence actual.
